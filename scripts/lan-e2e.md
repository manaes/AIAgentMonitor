# LAN 전송 종단 검증 (하드웨어 불필요)

CYD 펌웨어가 존재하기 **전에** 맥 쪽 LAN 전송 전 구간을 확인한다. 이것이 LAN 을
BLE 보다 먼저 한 이유 그 자체다 — 나중에 보드를 구워 놓고 무언가 실패했을 때
"맥은 이미 통과했다"고 말할 수 있어야 한다.

필요한 것은 `python3` 와 두 패키지뿐이다. `websocat` 은 쓰지 않는다.

```bash
python3 -m pip install cryptography websockets
```

> `websocat` 로는 이 프로토콜을 진행할 수 없다. 서버가 보낸 임시 공개키와 논스를
> 받아 **그 자리에서** 키를 합의하고 HMAC 을 계산해 다음 프레임을 보내야 하므로,
> 소켓과 암호를 한 프로세스가 같이 들고 있어야 순서가 선다. 사람이 두 도구
> 사이로 hex 를 옮겨 적는 것은 절차가 아니라 실수를 만드는 장치다.

## 0. 골든 벡터 관문 — **반드시 먼저**

```bash
python3 scripts/lan_e2e_client.py selftest
```

```
골든 벡터 대조:
  [OK]   transcript
  [OK]   code_binding
  [OK]   session_proof
  [OK]   pair_key
  [OK]   k_s2c
  [OK]   k_c2s
  [OK]   sealed_frame_0
  [OK]   sealed_frame_1
  [OK]   unseal(sealed_frame_1)
  [OK]   재전송 거절 (counter <= last_counter)
```

**이 순서를 뒤집으면 이 절차의 가치가 사라진다.** 관문을 지나기 전의 핸드셰이크
실패는 아무것도 말해 주지 않는다 — 맥이 틀린 것인지 파이썬이 틀린 것인지 구분할
수 없기 때문이다. 관문을 지난 뒤에는 이 클라이언트가 **기준**이고, 이후의 모든
실패는 맥의 것이다.

관문은 `scripts/lan_e2e_client.py` 의 모든 하위 명령이 시작할 때 자동으로 한 번 더
돈다. 어긋나면 소켓을 열지 않고 죽는다.

> 이 클라이언트는 `src-tauri/src/crypto` 를 부르지도 베끼지도 않는다. 스펙
> (`docs/superpowers/specs/2026-08-25-e2ee-protocol-v2-design.md`)만 보고 따로
> 구현한 것이다. 같은 코드가 자기 자신과 일치하는 것은 증거가 아니다.

## 1. 맥 준비 — **사람이 한다**

```bash
pnpm tauri dev
```

> 이미 설치본(`/Applications/AI Agent Monitor.app`)이 떠 있으면 먼저 종료한다.
> 중복 실행 방지 플러그인이 걸려 있어 두 번째 인스턴스는 기존 창만 앞으로
> 가져오고 스스로 끝난다 — dev 빌드의 LAN 서버는 뜨지 않는다.

메뉴 막대 아이콘 클릭 → 상세 창 → **Devices** 탭 → **LAN 공유** 를 켠다.

리스너가 실제로 섰는지는 화면 말고 포트로 확인한다:

```bash
lsof -nP -iTCP:4320 -sTCP:LISTEN
```

`0.0.0.0:4320 (LISTEN)` 이 보여야 한다. 안 보이면 Devices 패널의 빨간 줄을 읽는다
(이 앱은 로그 파일을 남기지 않으므로 그 줄이 유일한 경로다).

## 1-1. 맥이 스냅샷을 **언제** 보내는지 알고 시작한다

이 한 문단을 건너뛰면 정상 동작을 실패로 읽는다.

LAN 미러 게이트는 스로틀이 아니라 **변경 게이트**다. `EmitGate::should_emit` 은
내용 해시가 같으면 시간과 무관하게 `false` 를 돌려주고(`emitter.rs:18-19`),
`hash_snapshot` 에는 **타임스탬프가 없다**(`:37-57` — 에이전트 종류·rate·토큰
합계·쿼터·프로젝트만 넣는다). `lan/mod.rs:94-97` 이 그대로 적어 두었다:
「조용한 시간에는 봉인 카운터도 전진하지 않는다」.

| | 첫 한 장 | 그다음 |
|---|---|---|
| **페어링 직후**(§3) | **보장된다** — 게이트가 대상 검사 뒤에 있어 아무도 없을 때는 소비되지 않는다(`lan/mod.rs:481-488`) | 내용이 바뀌어야 온다 |
| **재연결 직후**(§4) | **보장되지 않는다** — 재연결은 `gate.reset()` 을 부르지 않는다(`reset` 은 `set_enabled(true)` 에서만, `lan/mod.rs:190`) | 내용이 바뀌어야 온다 |

**그래서 §3·§4·§5 를 도는 동안 Claude 나 Codex 세션을 하나 켜 두고 실제로
토큰을 쓰게 하라.** 그러지 않으면 `--listen 2` 이상은 유휴 맥에서 반드시
`[FAIL]` 이고, 그것은 맥의 결함이 아니다.

`--listen` 의 기본값이 1인 이유가 이것이다. 클라이언트는 장수가 모자라면
이 사정을 함께 찍는다 — 그래도 0장이면 그때가 맥의 결함이다.

## 2. 인가 없이 붙어만 있어 본다 — 페어링보다 **먼저**

페어링 창을 열기 전에 한다. 인가되지 않은 연결이 무엇을 받는지 보려면 인가된
연결이 하나도 없는 편이 깨끗하다.

```bash
python3 scripts/lan_e2e_client.py observe --seconds 180
```

- [ ] 아무것도 보내지 않았는데 **애플리케이션 프레임이 0장 / 0바이트**다
      (Ping/Pong 은 라이브러리가 주고받으므로 여기 세지 않는다)
- [ ] 맥이 **150초 언저리**에 스스로 끊는다 — `AUTH_DEADLINE`

두 번째 항목이 이 전송에서 자리 여덟 개(`MAX_CONNECTIONS`)가 실제로 회수된다는
유일한 근거다. 끊지 않고 180초를 넘기면 실패다.

## 3. 첫 페어링 — `HELLO2` / `CODE2`

Devices 탭에서 **페어링 시작** 을 누르고 화면의 6자리를 읽는다. **이 두 가지는
사람만 할 수 있다** — 코드는 오직 맥 화면으로만 나간다.

```bash
python3 scripts/lan_e2e_client.py pair          # 6자리를 물어본다
```

> `--code 123456` 으로 넘겨도 되지만 argv 는 `ps` 로 같은 기계의 다른 사용자에게
> 보이고 셸 히스토리에도 남는다. 생략하면 물어본다.

- [ ] `HELLO2:` 응답이 `{"ok":false,"v":2,"await":"code","epk":"…","nonce":"…"}` 다
- [ ] 그 응답에 **6자리 코드가 들어 있지 않다** (v2 는 `HMAC(code, transcript)` 만 보낸다)
- [ ] `CODE2:` 응답이 `{"ok":true,"v":2,"sealed":"…"}` 다
- [ ] 그 응답에 **32자리 토큰이 평문으로 들어 있지 않다**
- [ ] `sealed` 를 `k_pair` 로 풀면 `{"token":"<32 hex>"}` 가 나온다 (카운터 0)
- [ ] 이어서 오는 스냅샷 프레임이 **`{` 로 시작하지 않는다** — 평문 JSON 이 아니다
- [ ] 세션 키(`k_s2c`)로 풀면 맥 Detail 창과 같은 값의 JSON 이 나온다
- [ ] 프레임마다 카운터가 **전진**한다

클라이언트가 위 항목을 스스로 판정한다 — 카운터 전진까지 포함해서다(`unseal`
이 거절한다). 하나라도 어긋나면 `[FAIL]` 을 찍고 1로 끝난다.

**사람이 눈으로 해야 하는 것은 딱 하나다**: 「세션 키로 풀면 맥 Detail 창과 같은
값의 JSON 이 나온다」. 복호된 JSON 의 숫자와 상세 창의 숫자를 직접 비교하라 —
클라이언트는 그 JSON 이 열린다는 것만 알지 그 값이 맞는지는 모른다.

토큰은 `scripts/.lan-e2e-token.json` 에 저장된다. CYD 의 NVS 자리다.

## 4. 재연결 — `AUTH2` / `PROOF2`

**첫 페어링보다 이쪽이 CYD 의 일상이다.** 보드는 첫 페어링을 한 번 하고, 그 뒤로
켜질 때마다 이 경로만 탄다.

```bash
python3 scripts/lan_e2e_client.py reconnect --listen 1
```

- [ ] `AUTH2:` 응답이 `{"ok":false,"v":2,"epk":"…","nonce":"…"}` 다
- [ ] `PROOF2:` 응답이 `{"ok":true,"v":2}` 다
- [ ] 봉인된 스냅샷이 온다 — **카운터가 다시 0 부터 시작한다**(연결마다 새 키다).
      §1-1 대로 토큰이 실제로 소모되는 동안에만 온다. 유휴 맥에서 0장인 것은
      결함이 아니다
- [ ] 페어링 창을 열지 않았는데도 통과한다 (토큰 인증은 창과 무관하다)

토큰은 이 왕복에서도 링크를 건너지 않는다 — 나가는 것은 `HMAC(token, nonce ||
transcript)` 뿐이다.

### 4-1. 맥을 껐다 켜도 되는가

```bash
# 맥 앱을 종료했다가 다시 띄우고 LAN 공유를 켠 뒤
python3 scripts/lan_e2e_client.py reconnect --listen 0
```

- [ ] 같은 토큰으로 그대로 통과한다 (`--listen 0` — 여기서 보는 것은 인증이지
      스냅샷이 아니다)

이것이 통과하지 않으면 `Granted2` 를 받은 세션에서는 멀쩡히 동작하다가 **맥을
재시작하는 순간 기기가 영영 재연결하지 못한다**. 발급 신호(`granted`)가 디스크
쓰기까지 이어지는지를 보는 유일한 검사다.

## 5. 기기를 해제하면 즉시 끊긴다

```bash
python3 scripts/lan_e2e_client.py watch
```

붙어 있는 동안 Devices 탭의 기기 목록에서 그 기기를 **해제**한다.

- [ ] 해제하는 즉시 연결이 끊긴다 (`[OK] 맥이 연결을 놓았다`)

**이 검사는 끊김으로 끝나야만 통과다.** 조용히 타임아웃하면 `[FAIL]` 에 rc=1
이다 — 프레임이 0장인 것은 §1-1 대로 정상일 수 있지만, 해제를 눌렀는데도
끊기지 않는 것은 정상이 아니다. 해제를 누르지 않고 기다리기만 해도 `[FAIL]`
이 나오는 것이 맞다. 「아무 일도 일어나지 않았다」가 「해제하면 끊긴다」의
증거가 될 수는 없다.

토글을 끄는 것으로도 같은 일이 일어나야 한다.

## 6. 틀린 코드 다섯 번이면 창이 닫힌다

Devices 탭에서 **페어링 시작** 을 새로 누른 뒤:

```bash
python3 scripts/lan_e2e_client.py wrong-code --tries 6
```

- [ ] `관측한 left: [4, 3, 2, 1, 0, None]`
- [ ] `거절이 나온 단계: ['CODE2', 'CODE2', 'CODE2', 'CODE2', 'CODE2', 'HELLO2']`
- [ ] 화면에 「시도 5회가 모두 틀렸습니다」가 뜬다

**마지막 거절이 `CODE2` 가 아니라 `HELLO2` 에서 나오는 것이 정상이다.** 예산이
0 이면 `open_window` 가 창을 주지 않고(`ble/pairing.rs:551`) `HELLO2` 가 곧바로
벗은 `{"ok":false}` 를 돌려준다(`:715`) — 여섯 번째 시도는 `CODE2` 까지 가지
못한다. 스펙 5.2 표의 마지막 줄 「창이 닫혀 있음 → `{"ok":false}`」가 이것이다.
그 응답에는 `v` 필드가 없다.

**이 예산은 절대 넓히지 않는다.** 6자리의 엔트로피는 20비트뿐이고, 중간자 방어
논증(스펙 5.1) 전체가 "온라인 추측이 5회로 묶인다"에 걸려 있다.

`CODE2` 는 성공·실패와 무관하게 핸드셰이크를 소비하므로 매 시도가 `HELLO2` 부터
다시 시작한다 — 같은 transcript 로 여러 번 추측할 수 없다는 뜻이다. 클라이언트가
시도마다 연결을 새로 연다.

## 7. 뒷정리

- Devices 탭에서 테스트로 붙인 기기를 해제한다
- **LAN 공유를 다시 끈다** — 기본값은 꺼짐이다
- `scripts/.lan-e2e-token.json` 을 지운다

클라이언트는 토큰을 끝 4자리만 찍고 파일도 0600 으로 만든다. 그래도 이 파일의
내용은 **재연결 자격 그 자체**이므로 남겨 두지 않는다.

```bash
rm -f scripts/.lan-e2e-token.json
```

## 부록: 무엇이 선을 건너는가

이 절차가 확인하는 프레임 형식은 **스펙이 아니라 `src-tauri/src/lan/` 에서** 온
것이다. 전송마다 다르고, 스펙 7장의 iroh 줄에는 한 번 틀린 전례가 있다.

| 방향 | WebSocket 프레임 | 내용 |
|---|---|---|
| 기기 → 맥 | **텍스트** | `HELLO2:` `CODE2:` `AUTH2:` `PROOF2:` (UTF-8) |
| 맥 → 기기 | **텍스트** | `AuthReply` JSON |
| 맥 → 기기 | **바이너리** | 봉인 프레임 **원시 바이트 그대로** |

- 서버는 `Message::Text` 만 인증 프레임으로 올린다. 바이너리로 보낸 인증 프레임은
  `last_seen` 만 갱신하고 조용히 버려진다.
- 스냅샷은 hex 가 아니고 줄바꿈 구분자도 없다. **WebSocket 이 이미 프레임을
  나누므로 LAN 은 청킹하지 않는다.** iroh 는 다르다 — 그쪽은 hex + `\n` NDJSON 이다.
- 봉인 프레임 = `counter(8바이트 BE) || ciphertext || tag(16바이트)`,
  AEAD 논스 = `[0,0,0,0] || counter_BE`, AAD = `aim-v2`.
