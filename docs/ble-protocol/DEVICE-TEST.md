# 실기기 확인 절차 (1단계)

> BLE는 iOS 시뮬레이터에서 동작하지 않는다. 아래는 실제 iPhone이 있어야 하는 유일한 단계다.
> 작성일 2026-08-18 · 브랜치 `feat/ble-ios-mirror`

## 0. 준비 — 코드 서명 팀 지정 (한 번만)

기기 빌드는 Apple 개발자 팀이 지정돼야 통과한다. 이 맥에는 여러 조직의 인증서가 섞여 있어
**어느 계정을 `com.dgitx.aiagentmonitor.mirror` 에 묶을지는 사람이 골라야 한다.**

```bash
cd ios && tuist generate     # --no-open 없이 실행하면 Xcode 가 열린다
```

Xcode에서 `App` 타깃 → **Signing & Capabilities** → **Team** 드롭다운에서 본인 계정 선택.

무료 개발자 계정이면 설치본이 **7일 후 만료**되어 재설치가 필요하다. 유료(연 $99) 계정이면 1년이다.

> 팀을 고정하고 싶으면 `ios/Project.swift` 의 `App` 타깃에
> `settings: .settings(base: ["DEVELOPMENT_TEAM": "<팀ID>"])` 를 추가한 뒤 `tuist generate` 를 다시 돌린다.
> 팀 ID 는 Xcode 의 Team 드롭다운 또는 developer.apple.com 계정 페이지에서 확인한다.

## 1. Mac 쪽 준비

```bash
pnpm tauri dev
```

1. 상태 바 아이콘 클릭 → Detail 창
2. **Devices** 탭 (macOS에서만 보인다 — Windows에서는 의도적으로 숨겨진다)
3. **BLE 공유** 토글을 켠다
4. macOS가 블루투스 권한을 물으면 **허용**

   거부하면 패널에 빨간 글씨로 안내가 뜬다. 이 앱은 로그 파일을 남기지 않으므로(아래 참고)
   **이 화면이 실패 원인을 알 수 있는 유일한 경로**다.
5. 「광고 중 · AIM-*」 표시 확인

## 2. iPhone 쪽

1. iPhone을 맥에 연결
2. Xcode에서 `App` 스킴 + 연결된 iPhone 선택 → 실행
3. iPhone에서 블루투스 권한 **허용**

## 3. 확인 항목

- [ ] 상태 라벨이 `Mac 찾는 중…` → `연결 중…` → `연결됨` 순으로 바뀐다
- [ ] Mac의 Devices 탭에 기기가 하나 나타나고 MTU가 표시된다 (**보통 180~185**)
- [ ] iPhone 화면에 `{"v":1,"t":…}` 로 시작하는 JSON이 표시된다
- [ ] 수신 카운터가 **초당 약 1회** 증가한다
      (Mac에서 Claude Code를 돌려 토큰이 실제로 변할 때만 갱신된다 — 내용이 그대로면 보내지 않는다)
- [ ] **Mac에서 토글을 껐다가 다시 켜면 스트리밍이 재개된다** ← 가장 주의 깊게 볼 항목. 아래 참고
- [ ] iPhone을 들고 멀어졌다가 돌아오면 자동으로 재연결된다
- [ ] 제어센터에서 블루투스를 껐다 켜도 재연결된다 (공유가 켜져 있을 때만)
- [ ] **공유를 끈 상태에서** 제어센터 블루투스를 껐다 켜도 `AIM-*` 이 다시 광고되지 **않는다**

## 4. 특히 주의할 항목 — 껐다 켜기

`CBPeripheralManager` 에는 연결된 central 을 직접 끊는 API 가 없다. 그래서 공유를 끄면 GATT
서비스를 내리는 방식으로 "이 주변장치는 더 이상 없다"를 알린다. iOS 쪽은 그 신호를 받아
`didModifyServices` 에서 서비스를 다시 탐색하도록 구현해 뒀다(`BLEClient.swift:187`).

이 왕복이 실기기에서 실제로 성립하는지는 **코드만으로는 확정할 수 없어** 이 항목이 가장 중요하다.

실패하면 이렇게 보인다: **iPhone은 「연결됨」인데 Mac은 연결된 기기 없음, 데이터 0바이트.**
그 경우 iPhone 앱을 재시작하면 복구된다. 증상을 보면 알려달라 — 진단 지점이 특정돼 있다.

## 5. 알아둘 것 — 이 앱은 로그를 남기지 않는다

README 는 `~/Library/Logs/AIMonitor/app.log` 에 로그가 쌓인다고 적고 있으나, 실제로는
`tracing-subscriber` 의존성도 초기화 코드도 없어 **모든 `tracing::error!` 출력이 버려진다.**
해당 디렉토리는 비어 있다.

BLE 와 무관한 기존 문제이며 이번 브랜치에서 고치지 않았다. 그래서 BLE 오류만은 로그가 아니라
Devices 패널에 직접 띄우도록 만들었다. 앱 전역 로깅을 살릴지는 별도 판단이 필요하다.

## 6. 1단계 범위 밖 (의도적)

- **기기 인증이 없다.** 공유를 켜면 근처의 누구나 붙어서 화면을 볼 수 있다. 6자리 코드 페어링은
  3단계 범위이며, 그래서 토글 기본값이 **꺼짐**이고 패널에 경고 문구가 있다.
- iPhone 화면은 원본 JSON 덤프다. Detail 창과 똑같이 생긴 화면은 2단계에서 만든다.
- 백그라운드 동작과 알림은 없다(앱을 열어둔 동안만).
- 트리거 목록 전송은 아직 없다.
