# CYD 클라이언트 설계 — ESP32 Cheap Yellow Display

> 작성 2026-08-25
> 선행 스펙: `2026-08-25-e2ee-protocol-v2-design.md` — **이 스펙은 v2 위에서만 성립한다**
> 선행 스펙: `2026-08-25-shared-pairing-design.md` (공유 페어링)

## 1. 무엇을 만드는가

ESP32 Cheap Yellow Display(CYD)를 **세 번째 클라이언트**로 추가한다. 맥 화면의 미러를
책상 위 전용 기기에 띄운다.

맥 쪽에는 **세 번째 전송 브리지 `lan`** 이 생긴다. 페어링 창·6자리 코드·5회 예산·기기
목록은 지금 구조를 **그대로 공유한다** — 사용자 눈에는 Devices 탭 토글이 하나 느는 것뿐이다.

**1단계 LAN(WiFi + WebSocket) → 2단계 BLE 폴백.** 1단계를 먼저 하는 이유는 8장에 있다.

## 2. 하드웨어

| 항목 | 값 |
|---|---|
| 보드 | Sunton ESP32-2432S028R ("CYD") |
| MCU | ESP32-WROOM-32, 듀얼코어 Xtensa LX6 240MHz |
| 플래시 | 4MB |
| SRAM | 520KB |
| **PSRAM** | **없음** |
| 디스플레이 | 2.8" 320×240, ILI9341 (v3 변종은 ST7789) |
| 터치 | XPT2046 (저항막) |
| 무선 | WiFi + BT 4.2 |

**실물 확인 완료 (2026-08-26): `esp32-2432S028Rv3` — USB-C 와 마이크로 USB 가 둘 다
있는 판이고 디스플레이 컨트롤러가 ILI9341 이 아니라 ST7789 다.** 아래는 셋을 구분하는
원래 서술이며, 우리 보드는 v3 로 확정됐다.

**변종이 셋이다** — `esp32-2432S028R`(마이크로 USB), `esp32-2432S028Rv2`(USB-C),
`esp32-2432S028Rv3`(USB-C + 마이크로 USB, **ST7789**). 보드 정의 한 줄 차이지만 v3 는
디스플레이 컨트롤러가 다르다. **실물이 도착하면 어느 변종인지 먼저 확인한다.**

### 2.1 SPI 버스 함정 — 그리고 이 설계가 그것을 회피하는 방식

ESP32 의 하드웨어 SPI 버스는 2개인데 CYD 의 장치는 3개다(디스플레이 HSPI, 터치 VSPI,
SD VSPI). 셋을 동시에 쓰려면 터치를 소프트웨어 SPI 로 비트뱅잉하거나 LovyanGFX 로
버스를 가상 매핑해야 한다 — CYD 저장소 TROUBLESHOOTING 에 올라와 있는 알려진 문제다.

**이 설계는 SD 카드를 쓰지 않는다.** 폰트를 플래시에 배열로 내장하므로(6.3 참조) SD 가
필요 없고, 따라서 이 문제가 발생하지 않는다. 디스플레이 + 터치만 쓴다.

## 3. 왜 BLE 가 아니라 LAN 이 먼저인가

| | BLE | LAN (WiFi + WebSocket) |
|---|---|---|
| 맥 쪽 변경 | 없음 | 브리지 1개 + 라우트 1개 |
| 기기 쪽 난이도 | GATT 탐색 + 청크 재조립 + MTU 협상 | WebSocket 한 개 |
| **하드웨어 없이 검증** | **불가능** | **가능** — `websocat` 으로 전 구간 |
| 아이폰에 주는 위험 | 4.1 참조 | 없음 |
| 플래시 | NimBLE 200~300KB | BLE 스택 불필요 |
| 거리 | ~10m | 같은 망 전체 |
| 기기 설정 | 6자리 코드만 | WiFi 자격증명 + 6자리 코드 |

세 번째 줄이 결정적이다. **BLE 는 맥 쪽이든 기기 쪽이든 실기기 없이는 한 줄도 검증되지
않는다.** LAN 은 맥 쪽 전 구간을 하드웨어 없이 짜고 테스트하고 커밋할 수 있으므로,
기기가 도착했을 때 남은 미지수가 훨씬 적다.

### 3.1 BLE 를 나중으로 미루면서 함께 고쳐야 할 것

`ble/mod.rs:86` 이 청크 크기를 **인가된 구독자 전체의 최솟값**으로 정한다. 그리고
`framing.rs` 의 청크 상한은 255개다.

MTU 를 기본값 23 으로 둔 기기가 붙으면 본문이 17바이트가 되어 최대 페이로드가
17 × 255 = **4,335바이트**로 떨어진다. 스냅샷이 이를 넘으면 `chunk()` 가 `TooLarge` 를
돌려주고 `mod.rs:110` 이 프레임을 **모든 기기에 대해** 버린다. 그것도 `tracing::error!`
로만 남는데 이 앱에는 `tracing-subscriber` 가 없어 **아무 데도 보이지 않는다.**

즉 **MTU 가 낮은 기기 하나가 아이폰 미러를 조용히 죽일 수 있다.** 2단계에서 BLE 를 붙일
때 맥 쪽에 하한 방어를 함께 넣는다. 이 스펙의 1단계 범위는 아니지만 잊지 않기 위해
여기 적는다.

## 4. 맥 쪽 — `src-tauri/src/lan/mod.rs`

`network/mod.rs` 와 **같은 표면**을 갖는다. 세 브리지가 같은 모양이면 `lib.rs` 의 배선이
대칭이 되고, 하나만 고치고 다른 쪽을 잊는 드리프트가 줄어든다.

```rust
pub fn new(...) -> Self
pub fn is_enabled(&self) -> bool
pub fn set_enabled(&mut self, on: bool)
pub fn served_centrals(&self) -> Vec<CentralId>
// 봉인은 동기(페어링 잠금 필요), 쓰기는 비동기(잠금 불필요) — 잠금이 write 를
// 넘지 않게 호출부가 사이에서 drop 한다. network 브리지가 같은 모양이다.
pub fn prepare_snapshot(&mut self, snap: &Snapshot, now: SystemTime,
                        pairing: &mut PairingManager) -> Vec<(CentralId, Vec<u8>)>
pub async fn send_prepared(&mut self, lines: Vec<(CentralId, Vec<u8>)>)
pub fn handle_auth(&mut self, id: &CentralId, data: &[u8],
                   pairing: &mut PairingManager) -> AuthOutcome
//   AuthOutcome { payload, now_authorized, granted } — granted 는 새 토큰 발급
//   신호이고 v2 의 Granted2 도 포함해야 한다. 빠뜨리면 LAN 으로 페어링한 기기의
//   토큰이 디스크에 안 남아 맥 재시작 후 영영 재연결이 안 된다.
pub fn forget_central(&mut self, id: &CentralId)
pub fn drop_sessions(&mut self, ids: &[CentralId])
```

### 4.1 전송

- `axum` 에 `ws` 피처를 켠다(`axum 0.7`, 확인함).
- 라우트 하나: `GET /mirror` — WebSocket 업그레이드.
- 바인딩 `0.0.0.0:4320`. quota 프록시(4319) 바로 옆이다. `quota_proxy.rs` 의
  `TcpListener::bind` + `axum::serve` 패턴을 그대로 따른다.
- **기본 꺼짐.** 토글을 켤 때만 리스너가 뜬다.

### 4.2 연결 1개 = 세션 1개

WebSocket 연결 하나가 `CentralId` 하나에 대응한다. BLE 링크·iroh 스트림과 모델이 같아진다.

`CentralId` 형식은 `lan:<연결 일련번호>` 로 한다. IP 를 넣지 않는다 — 식별에 필요 없고,
기기 목록에 노출될 이유도 없다. 사용자에게 보이는 식별자는 기존과 같이
`peer_id = hex(SHA-256(token))[..8]` 이다.

연결이 끊기면 그 `CentralId` 의 인가를 즉시 지운다(BLE 의 `Disconnected` 와 동일).

### 4.3 프레임

- **인증**: 텍스트 프레임. `HELLO2:` / `CODE2:` / `AUTH2:` / `PROOF2:` 를 받아
  `handle_auth` 에 **그대로** 넘기고, 응답은 `AuthReply::to_json_bytes()` **그대로**.
  새 포맷을 만들지 않는다.
- **스냅샷**: 바이너리 프레임. E2EE v2 의 봉인 프레임
  (`counter(8B BE) || ciphertext || tag`)을 그대로 싣는다.
- **청킹 없음.** WebSocket 이 프레이밍을 한다. 255청크 상한도 MTU 문제도 존재하지 않는다.
- 인가 전에는 스냅샷을 **0바이트** 보낸다.

### 4.4 발견 (discovery)

- **주 경로**: mDNS 게시. 서비스 `_aim._tcp.local`, 포트 4320, TXT 에 `v=2`.
  Rust 는 `mdns-sd 0.21.0`(확인함), ESP32 는 `ESPmDNS.h`(코어 내장).
- **대체 경로**: 기기의 WiFi 설정 포털에서 맥 IP 를 직접 입력받는다(5.2). DHCP 로 IP 가
  바뀌면 mDNS 가 해결하고, mDNS 가 막힌 망에서는 수동 입력이 해결한다.
- 맥 UI 는 켜졌을 때 `IP:4320` 을 표시한다 — 수동 입력을 위해 필요하다.

### 4.5 UI

`DevicePanel.svelte` 에 **세 번째 토글**을 추가한다. BLE·네트워크와 독립이다.
페어링 영역과 기기 목록은 이미 하나로 합쳐져 있으므로 그대로 쓴다.

LAN 이 켜져 있고 페어링 창이 열려 있으면, 6자리 코드 옆에 `IP:4320` 을 함께 보여준다.
QR 은 만들지 않는다 — **CYD 에는 카메라가 없다.**

## 5. 기기 쪽

### 5.1 툴체인

- PlatformIO. 보드 정의는 `rzeldent/platformio-espressif32-sunton`.
- 그래픽은 같은 저자의 `esp32-smartdisplay` — 이 보드들용 LVGL 드라이버와 터치 보정을
  제공한다. 디스플레이 드라이버를 직접 쓰지 않는다.
- WebSocket 클라이언트: `Links2004/arduinoWebSockets`.
- 암호: monocypher 단일 파일(E2EE 스펙 3장 참조).
- 파티션: 기본으로 시작하고, 부족하면 OTA 없는 커스텀(앱 2MB + 나머지)으로 바꾼다.
  **BLE 스택을 쓰지 않으므로 1단계에서는 여유가 있다.**

### 5.2 WiFi 와 맥 주소 설정

WiFiManager 캡티브 포털을 쓴다. 저항막 화면에 SSID·비밀번호를 치는 것보다 폰으로 붙는
편이 낫다. **같은 포털에서 맥 IP 도 함께 입력받는다**(4.4 의 대체 경로).

설정은 NVS 에 저장한다. 부팅하면 저장된 WiFi 로 붙고, 실패하면 포털을 다시 연다.

### 5.3 화면

**2장이다.** 터치로 전환한다.

**① 에이전트 카드 페이지** — 카드 하나에 에이전트 하나.

표시할 에이전트 선택은 **맥의 설정을 그대로 따른다.** 필터가 Rust 백엔드에 있으므로
(`settings.rs` 의 `enabled_agents`) 스냅샷에 이미 반영되어 도착한다 — CYD 는 온 것을
그리기만 하면 되고, 기기 쪽에 별도 설정을 두지 않는다. iOS 미러와 같은 방식이다.
- 이름 (`Claude Code` / `Codex` / `Antigravity`)
- 5h 사용률 바 + 퍼센트. **70%/90% 경계에서 색이 바뀐다 — 맥·iOS 와 같은 규칙을 쓴다.**
- tok/s
- 리셋 카운트다운
- 주간 값이 있으면 주간 바도

**② 세션 목록 페이지** — LVGL `list` 위젯이 스크롤을 해결한다.
- 프로젝트 이름, 모델, 상태 점(active/idle/dormant), 상대 시각
- 최근 활동순 정렬 — iOS 미러와 같은 규칙

**③ 페어링 화면** — 인가되지 않았을 때 나온다. LVGL `btnmatrix` 로 6자리 키패드.
남은 시간과 남은 시도 횟수를 함께 보여준다.

**표시 규칙은 맥·iOS 와 같아야 한다.** 색 경계, 정렬 순서, 상태 단어, 시각 표기 —
세 화면이 어긋나면 미러가 아니다.

### 5.4 폰트 — 한글

화면의 문자열은 두 종류이고 비용이 전혀 다르다.

**① UI 라벨** — "연결됨", "남음", "사용률" 같은 우리가 쓰는 고정 문구. **빌드 시점에
글자가 전부 정해져 있으므로 쓰는 음절만 골라 구울 수 있다.** `lv_font_conv` 로 서브셋
폰트를 만든다. 실제 쓰는 음절이 50~60자면 16px 기준 **15~20KB**. 플래시에 배열로 내장하며
SPIFFS 도 SD 도 필요 없다.

**② 사용자 데이터** — 프로젝트 이름, 모델명. 어떤 글자가 올지 모른다.

②에 대해 **한글을 넣지 않는다.** 근거는 비용이 아니라 필요다 — `~/.claude/projects/` 를
확인한 결과 실제 프로젝트 이름이 전부 ASCII 다(`AIAgentMonitor`, `nViewer`, `Seqnex`,
`Routine`, `App` …). 모델명도 항상 ASCII 다. 지금 이득이 없다.

비용 자체는 생각보다 크지 않다. 완성형 2350자를 16px LVGL 폰트로 넣으면
**bpp=1 에서 약 95KB, bpp=4(안티에일리어싱)에서 약 320KB** 다 — 글리프당 비트맵
(16×16÷8 = 32바이트 / 16×16÷2 = 128바이트)에 서술자 약 8바이트를 더한 값이다.
2MB 앱 파티션이면 들어간다. **따라서 이것은 YAGNI 판단이지 불가능 판단이 아니다.**

**대신 비ASCII 글자가 오면 조용히 대체 문자로 그린다.** 깨진 화면이나 크래시가 아니라
읽을 수 없다는 것이 보이는 상태로 떨어져야 한다.

**업그레이드 경로**(지금 하지 않음): 한글 폴더명을 쓰게 되면 완성형 폰트를 앱에 함께
넣거나(bpp=1 이면 95KB) SPIFFS 로 뺀다. SD 로 빼기로 하면 2.1 의 SPI 버스 문제를 함께
풀어야 하므로, 플래시에 넣는 쪽을 먼저 검토한다.

### 5.5 인증 상태 기계

iOS 의 `BLEClient.decide` 와 **같은 결정**을 이식한다. **순수 함수로 뽑아 테스트로
고정한다** — 상태 기계를 연결 코드 안에 녹여넣지 않는다.

특히 iOS 에서 최근 겪은 두 버그를 여기서 되풀이하지 않는다.

1. **방금 입력한 코드가 저장된 토큰보다 우선한다.** 사용자가 키패드로 코드를 넣었다는
   것은 "새로 페어링하겠다"는 명시적 의사다. 맥이 토큰을 이미 폐기했다면 토큰 재인증은
   반드시 거부되고, 그 사이 코드는 쓰이지도 못한다.
2. **성공할 수 없는 재시도를 하지 않는다.** 인증 거부/`needsPairing` 은 사용자가 코드를
   다시 넣어야 풀린다. 이때 재연결 루프를 돌리면 화면만 깜빡인다.

### 5.6 토큰 저장

NVS(`Preferences`). **평문이다** — 플래시 암호화를 켜지 않는 한 기기를 주운 사람이 읽을
수 있다. iOS Keychain 과 다르다. 대응은 맥에서의 기기별 해제(`peer_id`)뿐이다. 7장에
다시 적는다.

## 6. 데이터 흐름

```
맥                                              CYD
──                                              ───
[토글 켬] → 리스너 4320, mDNS 게시
[페어링 시작] → 6자리 코드 (맥 화면에만)
                                                부팅 → WiFi → mDNS 조회
                          ←──── WS 연결 ────────
                          ←──── HELLO2:<cpk> ───
   ──── epk, nonce ──────→
                                                키패드 화면
                          ←──── CODE2:<cbind> ──   (사용자가 6자리 입력)
   ──── sealed{token} ───→                       토큰 → NVS
   ══════ 이후 봉인된 스냅샷 ═══════════════════→  카드/세션 화면

재부팅 후
                          ←──── AUTH2:<cpk> ────
   ──── epk, nonce ──────→
                          ←──── PROOF2:<proof> ─
   ──── {"ok":true} ─────→
   ══════ 봉인된 스냅샷 ═══════════════════════→
```

## 7. 보안

### 7.1 유지되는 것

E2EE v2 스펙 12장의 제약을 전부 그대로 따른다. LAN 공유도 **기본 꺼짐**이다.

E2EE v2 덕분에 LAN 이 평문이 아니다 — 같은 WiFi 의 다른 기기는 스냅샷을 읽을 수 없고,
페어링 순간의 토큰도 봉인되어 건넌다.

### 7.2 새로 생기는 위험

1. **도달 범위가 넓어진다.** BLE 는 "10m 안에 있어야 한다"는 것 자체가 방어의 일부였다.
   LAN 은 망 전체다. 이제 토큰과 코드 바인딩이 유일한 방어선이다 — 그래서 E2EE 를
   먼저 한다.
2. **NVS 평문 토큰.** 5.6 참조. 기기를 물리적으로 잃으면 그 토큰은 폐기해야 한다.
   맥의 기기별 해제로 대응한다.
3. **macOS 방화벽 프롬프트.** `0.0.0.0` 바인딩이므로 사용자가 허용해야 한다. 거부하면
   Devices 패널에 이유가 보여야 한다 — 이 앱은 로그 파일을 남기지 않으므로 패널이
   실패 원인을 알 수 있는 유일한 경로다(BLE 권한 거부 때와 같은 방침).
4. **포트 4320 이 이미 쓰이는 경우.** 바인딩 실패를 조용히 삼키지 않는다. quota 프록시는
   실패 시 `tracing::warn!` 만 남기는데(`quota_proxy.rs:249`), 그것은 opt-in 기능이라
   그렇다. LAN 공유는 사용자가 방금 켠 기능이므로 **패널에 오류를 표시한다.**

## 8. 테스트

### 8.1 하드웨어 없이 되는 것 (맥 쪽 전부)

- `lan` 브리지 유닛테스트 — 기존 `FakePeripheral` 과 같은 방식으로 전송을 가짜로 둔다.
- `websocat` 종단 검증: 연결 → `HELLO2` → 코드 입력 → 토큰 수령 → 재연결 → `PROOF2` →
  봉인된 스냅샷 복호. **이것이 LAN 을 먼저 하는 이유다.**
- E2EE 골든 벡터로 봉인·해제 대조.

반드시 순수 함수로 뽑아 테스트할 것:
- 인가되지 않은 연결에 스냅샷이 0바이트 나간다
- 연결이 끊기면 인가가 즉시 사라진다
- 토글을 끄면 리스너가 실제로 닫히고 기존 세션이 끊긴다
- 포트 바인딩 실패가 패널에 오류로 나타난다

각 테스트는 **뮤테이션으로 검증한다.**

### 8.2 하드웨어가 필요한 것

- WiFi 포털 → 연결 → mDNS 발견
- 키패드로 6자리 입력 → 페어링
- 재부팅 후 토큰 재인증
- 화면이 맥 Detail 창과 **시각적으로 일치하는가** — 이것이 완료 판정이다
  (`docs/ble-protocol/DEVICE-TEST.md` 의 iOS 판정과 같은 기준)
- 한글 라벨이 깨지지 않는가, 비ASCII 프로젝트 이름이 대체 문자로 떨어지는가

절차는 구현 시 `docs/ble-protocol/DEVICE-TEST.md` 에 CYD 절을 추가해 남긴다.

## 9. 2단계 — BLE 폴백

1단계가 끝난 뒤에 한다. 그때 함께 해야 할 것:

- NimBLE-Arduino 센트럴 (Bluedroid 아님 — 플래시 167~254KB 차이)
- `NimBLEDevice::setMTU()` 로 MTU 를 충분히 올린다
- **맥 쪽에 MTU 하한 방어**(3.1) — 이것 없이 BLE 를 붙이면 아이폰 미러가 위험하다
- 플래시 재점검. NimBLE + 한글 서브셋 폰트 + LVGL 이 함께 들어가야 하므로 커스텀
  파티션이 필요할 수 있다
- 전송 선택 UI — 기기에서 LAN/BLE 중 무엇으로 붙을지

페어링은 이미 공유되므로 **기기 목록은 하나로 유지된다.** 같은 CYD 가 LAN 으로 붙든
BLE 로 붙든 사용자에게는 같은 기기다.

## 10. 이 스펙이 다루지 않는 것

- CYD 에서 맥을 **제어**하는 기능(세션 종료, 설정 변경 등). 미러는 읽기 전용이다.
- 여러 대의 맥을 한 CYD 로 보는 것.
- 배터리·절전. 상시 USB 전원을 가정한다.
- OTA 펌웨어 업데이트.
- v3 변종(ST7789)의 화면 색 보정 차이. 실물 확인 후 필요하면 별도로 다룬다.
